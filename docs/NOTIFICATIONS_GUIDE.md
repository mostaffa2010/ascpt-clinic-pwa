# دليل نظام الإشعارات الفورية الشامل (ASCPT Push & In-App Notifications Guide)

## نظرة عامة (Architecture Overview)

يعتمد نظام الإشعارات في مركز الإسكندرية التخصصي للعلاج الطبيعي (ASCPT) على **معمارية ثلاثية متكاملة** تضمن إيصال التنبيه فورياً للهاتف حتى لو كان التطبيق مغلقاً في الخلفية، مع حفظ نسخة سحابية دائمة في صندوق وارد المستخدم بالواجهة:

```text
               ┌────────────────────────┐
               │    1. مشغّل الحدث      │
               │ (استقبال / طبيب معالج) │
               └───────────┬────────────┘
                           │ استدعاء API
                           ▼
               ┌────────────────────────┐
               │  2. السيرفر السحابي   │
               │ /api/notifications/send│
               └─────┬────────────┬─────┘
                     │            │
      تسجيل سحابي     │            │ إرسال عبر FCM
      في Firestore   │            │ مع الـ VAPID Key
                     ▼            ▼
         ┌──────────────────┐  ┌──────────────────────┐
         │ 3. قاعدة البيانات│  │ 4. هاتف المستلم      │
         │ users/{uid}/     │  │ Service Worker (sw)  │
         │   notifications  │  │   تنبيه منبثق وهزاز  │
         └─────────┬────────┘  └──────────┬───────────┘
                   │                      │
                   ▼                      ▼
         ┌────────────────────────────────────────────┐
         │ 5. واجهة الاستخدام (UI)                    │
         │ جرس التنبيهات + عداد أحمر + قائمة منسدلة  │
         └────────────────────────────────────────────┘
```

## المكونات الرئيسية للنظام

1. **الباك إند والسيرفر (`api/notifications/send.js`):**
   - نقطة نهاية بدون خادم (Vercel Serverless Function) مبنية عبر `firebase-admin/messaging` و `firebase-admin/firestore`.
   - تدعم التوجيه بالدور الوظيفي (`role: 'doctor' | 'receptionist' | 'admin'`) أو بمستخدم محدد (`doctorUid` / `recipientUid`).
   - تنظيف ذاتي للأجهزة المنتهية (Self-Healing Token Hygiene): عند إفادة خوادم Google بانتهاء صلاحية جهاز أو مسحه للتطبيق، يتم حذفه تلقائياً من Firestore لمنع تراكم الرموز الميتة.

2. **عامل الخدمة بالخلفية (`sw.js`):**
   - يستمع لحدث `push` في خلفية الهاتف ويعرض الإشعار بهوية المركز وألوانه مع الاهتزاز والصوت.
   - يستمع لحدث `notificationclick` لفتح التطبيق وتوجيه المستخدم للشاشة المحددة مباشرة (Deep Linking).
   - **أمان الكاش والأوفلاين:** مستمعات الإشعارات معزولة تماماً ولا تمس كاش ملفات الـ App Shell أو الأوفلاين.

3. **مدير الإشعارات بالواجهة (`js/notifications.js`):**
   - يدير طلب إذن الإشعارات وتوليد الـ Token وحفظه في Firestore عند الضغط على زر التفعيل.
   - يستمع لحظياً للتنبيهات الواردة لحساب المستخدم ويحدّث عداد الجرس فوراً.
   - يوفر دالة إرسال خاطفة ومحمية من انقطاع الإنترنت (`NotificationsManager.sendNotification`).

4. **عناصر الواجهة (`index.html` + `css/style.css`):**
   - زر الجرس بجوار اسم المستخدم في الترويسة العلوية.
   - شارة حمراء دائرية بارزة (`notification-badge`) بنص أبيض عريض عند وجود تنبيهات غير مقروءة.
   - قائمة منسدلة أنيقة (`notification-dropdown`) تتضمن زر "قراءة الكل" وقائمة الإشعارات مع إمكانية الضغط للانتقال السريع.
   - **عزل تام للطباعة:** كافة عناصر الإشعارات تحمل كلاس `no-print` ومدرجة في `print.css` لضمان عدم ظهور أي أثر لها في الطباعة أو الـ PDF.

## كيف تضيف نوع إشعار جديد في 3 خطوات بسيطة؟ (Template)

إذا أردت مستقبلاً إضافة أي إشعار جديد في أي ملف (مثلاً: تنبيه عند تسجيل مصروف كبير، أو تجديد موافقة تأمين)، اتبع هذه الخطوات الثلاث فقط:

### الخطوة 1: استدعاء دالة الإرسال عند وقوع الحدث
في أي ملف جافاسكربت (`patients.js`, `finance.js`, `claims.js`... إلخ):

```javascript
// أرسل الإشعار عبر مدير الإشعارات الموحد
if (window.app?.notificationsManager) {
  try {
    window.app.notificationsManager.sendNotification({
      type: 'your_custom_type',             // اسم نوع الإشعار (بالإنجليزية)
      title: 'عنوان الإشعار هنا',           // العنوان الرئيسي
      body: 'تفاصيل الإشعار المقتضبة هنا', // نص التنبيه
      target: {
        role: 'doctor',                     // 'doctor' أو 'receptionist' أو 'admin' أو 'all'
        doctorUid: 'TARGET_DOCTOR_UID'      // اختياري: إذا كان موجهاً لطبيب معين فقط
      },
      data: {
        screen: 'patients',                 // الشاشة المراد فتحها عند الضغط: 'patients' | 'sessions' | 'appointments' | 'finance'
        patientId: 'PATIENT_ID'             // اختياري: لفتح شيت مريض معين تلقائياً
      }
    });
  } catch (err) {
    console.warn('Notification notice:', err);
  }
}
```

### الخطوة 2 (اختيارية): تخصيص الأيقونة واللون في القائمة المنسدلة
افتح ملف `js/notifications.js` واذهب إلى دالة `renderNotifications()`، وأضف نوعك في جملة الـ `if`:

```javascript
} else if (n.type === 'your_custom_type') {
  iconClass = 'fa-solid fa-bell';      // أيقونة FontAwesome المناسبة
  iconColor = '#0284c7';               // لون الأيقونة
  iconBg = 'rgba(2, 132, 199, 0.12)';  // خلفية ناعمة للأيقونة
}
```

### الخطوة 3: انتهى!
لا تحتاج لتعديل قاعدة البيانات أو السيرفر أو ملفات الـ Service Worker؛ فالسيرفر والـ Service Worker مبرمجان للتعامل تلقائياً مع أي `type` وبيانات مخصصة.

## قائمة الإشعارات المعتمدة حالياً في المركز

| نوع الإشعار (`type`) | المشغل (Trigger) | المستلم (Recipient) | الهدف التشغيلي |
| :--- | :--- | :--- | :--- |
| `patient_checkin` | الاستقبال يسجل حضور جلسة أو كشف لمريض | الطبيب المعالج للحالة | تنبيه الطبيب بوصول المريض في صالة الانتظار لبدء الجلسة |
| `appointment_booked` | الاستقبال يثبت حجز موعد دوري جديد | الطبيب المعالج | تنبيه الطبيب بإضافة حالة جديدة لجدوله الأسبوعي |
| `session_completed` | الطبيب يضغط "تم" على موعد بداشبورد الطبيب | موظفو الاستقبال | إشعار الاستقبال بانتهاء الجلسة لمتابعة الحسابات أو خروج الحالة |
| `cash_handoff` | الاستقبال يؤكد تسليم عهدة نقدية الدرج | إدارة المركز (Admin) | توثيق استلام النقدية ومطابقة الخزينة اليومية فورياً |
| `admin_broadcast` | الإدارة ترسل تنبيهاً عاماً | كافة أفراد الطاقم | رسائل التنبيهات الإدارية والمواعيد الطارئة |

## صمامات الأمان وقواعد العمل (Best Practices)

1. **العمل دون اتصال (Offline Resilience):**
   دالة `sendNotification` تفحص أولاً `navigator.onLine`؛ فإذا كان الجهاز غير متصل بالإنترنت، يتم تخطي طلب الإشعار بسلاسة دون إظهار أي رسالة خطأ أو تعطيل تسجيل الجلسة أو المريض.
2. **عدم استهلاك رصيد قراءات Firestore:**
   إرسال الإشعارات يتم عبر السيرفر الخارجي، فلا يستهلك أي قراءة في الـ Free Tier لفايرستور من أجهزة العيادة.
3. **حماية الترويسة والطباعة:**
   كل ما يتعلق بمركز الإشعارات والجرس مخصص للشاشات التفاعلية فقط ومحجوب تماماً عن أي مخرجات ورقية أو ملفات PDF.

## ملحق الإصدار 2.10.1: معالجة تصاريح Firestore والتصميم المخصص

### 1. معالجة خطأ الصلاحيات (`Missing or insufficient permissions`):
- **السبب:** قواعد أمان Firestore (Security Rules) في Firebase Console تحظر بطبيعتها كتابة أي عميل عادي داخل مسار `users/{uid}`.
- **الحل الهندسي:** تم توجيه حفظ وتحديث وحذف رموز الأجهزة (Tokens) وتحديد المقروء عبر دالة سيرفر متميزة (`/api/notifications/token.js`) تعمل بصلاحيات المشرف الكاملة (Firebase Admin SDK).
- **قواعد Firestore الإضافية (اختيارية للمزامنة اللحظية المباشرة):**
  في حال رغبتك بتفعيل استماع الـ onSnapshot المباشر عبر Firebase Console، يمكن إضافة القواعد التالية:
  ```javascript
  match /users/{userId}/fcm_tokens/{tokenId} {
    allow read, write: if request.auth != null && request.auth.uid == userId;
  }
  match /users/{userId}/notifications/{notifId} {
    allow read, update: if request.auth != null && request.auth.uid == userId;
  }
  ```

### 2. محاذاة نافذة الإشعارات المنسدلة على الموبايل:
- تم استبدال المحاذاة المطلقة القديمة (`position: absolute; right: 0`) بمحاذاة ثابتة ومركزية للشاشات الذكية:
  `position: fixed; top: 68px; left: 12px; right: 12px; max-width: 380px; margin: 0 auto;`
- يضمن هذا التعديل ظهور النافذة كاملة بهوامش متساوية وبدون أي قطع جانبي على كافة أحجام الشاشات.

### 3. النافذة التمهيدية المخصصة (ASCPT Custom Permission Primer):
- **حقيقة تقنية:** نافذة الموبايل المنبثقة أسفل الشاشة (Allow / Don't allow) هي نافذة حماية إجبارية من نظام أندرويد (OS Security Prompt) لا يمكن لأي تطبيق في العالم تعديلها أو تجاوزها.
- **التصميم المخصص:** قمنا بإضافة نافذة داخلية أنيقة بهوية وألوان المركز (`#modal-notification-primer`) تفتح فور الضغط على زر "تفعيل"، وتشرح للمستخدم القيمة السريرية للتنبيهات بلغة عربية مريحة وتوضح له أن تأكيد الأمان التلقائي للهاتف سيظهر تالياً، مما يجعل تجربة الاستخدام احترافية ومطمئنة 100%.
