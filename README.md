## ما الجديد في الإصدار (v2.2.0) - المحرك الأصيل للمواعيد الدورية الأسبوعية:
1. **الجدول الدوري الأسبوعي الأصيل (Weekly Recurring Master Schedule):**
   - حجز الموعد يثبت مرة واحدة بنمط الأيام (سبت - إثنين - أربع / أحد - ثلاثاء - خميس / يومياً / مخصص) والساعة المحددة.
   - يسمّع الحجز تلقائياً في كافة الأسابيع القادمة دون أي حاجة لنسخ المواعيد تاريخاً بتاريخ.
2. **شاشتا عرض متكاملتان (Dual Operational Views):**
   - **اليوم التشغيلي (Daily Operations View):** عرض بطاقات اليوم، التحقق التلقائي من الحضور عبر الجلسات، كروت الأطباء، وحساب الطاقة الاستيعابية الفورية (الأسرة الشاغرة والممتلئة).
   - **الجدول الأسبوعي العام (Weekly Master Timetable):** خريطة بانورامية لجميع أيام الأسبوع (السبت إلى الخميس) توضح توزيع المرضى والأطباء والسعة المشغولة والمتاحة للتسكين الفوري.
3. **الاستثناءات اليومية الذكية (Daily Exceptions):**
   - زر سريع "اعتذار عن جلسة اليوم فقط": يسجل استثناء لتاريخ اليوم دون مساس بالموعد في باقي الأيام والأسابيع.
4. **إنهاء الحجز الدوري وتفريغ المكان (Discharge & Free Slot):**
   - بمجرد انتهاء كورس العلاج للمريض، يتم إنهاء الحجز بضغطة واحدة ليفرغ مكانه في كافة الأسابيع القادمة تلقائياً.
5. **تعديل الموعد والأيام بنقرة واحدة:**
   - إمكانية تعديل الطبيب، أو الفترة، أو أيام الحضور الأسبوعية في مكان واحد وبشكل لحظي.

## المعمارية الهندسية والإنتاجية (Production Architecture)

- **نمط النظام:** Single-Tenant Architecture (مشروع Firebase مستقل تماماً وخاص بمركز ASCPT).
- **قاعدة البيانات السحابية:** Cloud Firestore بنظام المجموعات المباشرة:
  - `patients/{patientId}`: ملفات المرضى والشيتات الطبية السريرية.
  - `sessions/{sessionId}`: تسجيل حضور الجلسات وتوريد المبالغ ونسب التحمل.
  - `expenses/{expenseId}`: مصروفات المركز التشغيلية.
  - `users/{uid}`: حسابات وبيانات الطاقم الطبي والإداري.
  - `audit_logs/{logId}`: سجل رقابي وتدقيق متكامل (Hybrid Audit Architecture):
    - العمليات الإدارية الحساسة (إنشاء، حذف، تغيير كلمة السر، وتفعيل/تعطيل الموظفين) تُسجل موثقة من جهة الخادم عبر Firebase Admin SDK (`/api/admin/users`).
    - العمليات التشغيلية (إضافة/تعديل/حذف المرضى، الجلسات، المصروفات) تُسجل بنمط Append-Only محمي من جهة العميل مع تحقق قواعد Firestore من تطابق هوية الكاتب (`userId == request.auth.uid`) وحظر أي تعديل أو حذف نهائياً.
- **الأمان والصلاحيات (Security & RBAC):**
  - اعتماد قواعد أمان صارمة في Cloud Firestore Security Rules بنمط Fail-Closed لمنع أي وصول غير مصرح به.
  - إدارة الحسابات وإضافة وتعديل وحذف الموظفين تتم حصرياً عبر نقطة نهاية خادم محمية (`/api/admin/users`) بواسطة Firebase Admin SDK.
- **العمل دون اتصال (Offline-First Resilience):**
  - تفعيل التخزين المؤقت المحلي متعدد النوافذ عبر Cloud Firestore IndexedDB Persistent Cache.
- **نظام التصدير والطباعة:**
  - محرك تصدير الإكسيل المعتمد لتقارير الإيرادات اليومية والشهرية بدقة وتصنيف كامل.
- **نظام التصميم الموحد للموبايل (Mobile Design System Tokens):**
  - اعتماد أبعاد قياسية للأزرار والكبسولات (`30px` / `38px` / `44px`)، وحظر تثبيت أزرار عائمة عشوائية فوق شريط التنقل السفلي.
  - تطبيق نظام الهوية البصرية للجنس الطبي (Clinical Gender Theming) بتدرجات زرقاء للذكور ووردية للإناث.
  - إلغاء الحاويات المتداخلة المزدوجة (Card-in-Card) وتوفير تجربة إدخال خاطفة (Fast-Track Check-in).
- **منظومة الاختبارات الآلية للحسابات الحساسة (Automated Test Suite):**
  - تشغيل اختبارات برمجية دورية عبر `npm test` للتأكد الدائم من صحة معادلات رصيد التأمين، والمطابقة المالية اليومية للخزينة، وحسابات المطالبات بدقة 100%.

### تحديثات الإصدار v2.0.2 (Firestore Free-Tier Optimization & Real-Time Sync):
- **الاستماع اللحظي التلقائي (Real-Time onSnapshot):** ربط جلسات ومواعيد اليوم بمستمعات سحابية مباشرة للتحديث الفوري عبر كل أجهزة المركز (استقبال/أطباء) بأقل تكلفة قراءات (قراءة واحدة للمستند الجديد وصفية للحذف).
- **إلغاء الاستعلامات المتكررة (Zero N+1 Queries):** الاعتماد المباشر على بيانات الجلسات المسجلة ورقم الجلسة المخزن مسبقاً بدلاً من تكرار استعلامات تاريخ المريض في حلقات متكررة.
- **تأمين حدود الاستعلامات (Strict Scoped Queries):** حظر استدعاءات الجلسات المفتوحة في شاشة المطالبات وحصرها دائماً في النطاق الزمني المحدد أو الشهر الحالي.
- **التحميل الكسول الذكي (Lazy Loading):** منع جلب بيانات الحسابات والمطالبات والمواعيد دفعة واحدة في الخلفية عند فتح التطبيق، وقصر التحميل على الشاشة النشطة فقط.
- **تثبيت الخيارات السريرية والشركات محلياً:** حفظ خيارات المركز وشركات التأمين في التخزين المحلي الدائم، وتخطي 7 قراءات سحابية في كل عملية إعادة تحميل.

### تحديثات الإصدار v2.1.3 (Firestore Runaway Reads Optimization):
- **معالجة استهلاك قراءات Firestore المرتفعة:** استبدال المستمعات اللحظية المفتوحة لكامل مجموعات المرضى (`patients`) والمواعيد (`appointments`) بنمط مستند الإصدار الخفيف (`meta/syncVersion`).
- **تحويل تكلفة المزامنة اللحظية من O(N) إلى O(1):** يستمع كل جهاز نشط الآن إلى مستند واحد فقط (`meta/syncVersion`) بكلفة قراءة واحدة فقط لكل تحديث فعلي، بدلاً من إعادة جلب كافة مستندات المجموعة عند كل إعادة تحميل للتبويب أو اهتزاز في اتصال الشبكة.
- **زيادة الإصدار الذري عند التعديل:** تحديث تلقائي للحقلين `patientsVersion` و `appointmentsVersion` عبر الدالة الذرية `increment(1)` عند إضافة أو تعديل أو حذف أي مريض أو موعد.
- **الحفاظ التام على المزامنة الحية وعمل الأوفلاين:** انعكاس التغييرات فورياً بين كافة أجهزة المركز، مع الاعتماد التام على التخزين المحلي المؤقت (IndexedDB / LocalStorage) لحماية العمل دون اتصال.
- **تحديث قواعد أمان Firestore:** إضافة تصريح القراءة والكتابة على `/meta/syncVersion` لكافة أفراد طاقم العمل النشطين والمعتمدين (`isUserActive()`).
